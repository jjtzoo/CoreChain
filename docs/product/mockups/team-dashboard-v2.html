Team dashboard, second pass: adapted from a SaaS reference, not copied

The first built pass (2026-09-22) was three flat text cards. This pass studies a generic project-management dashboard the owner shared as a design reference — persistent nav, KPI cards, charts, a workload view, quick actions — and re-derives each idea from CoreChain's own data instead of reusing its layout, tasks/projects language, or colours.

Hole names and planned depths are real (Alberta Geological Survey, AGS DIG 2024-0022). Metres, recovery, people and times are illustrative. Colours are the web app's own tokens, including the success/copper/danger tokens added 2026-09-22.

1 · Team dashboard

Everything a manager needs, one screen, still read-only

The reference's "tasks/projects/team" tabs, donut chart and generic task-creation form don't exist in CoreChain's domain, so none of them are copied. What's kept is the underlying idea each serves: a persistent way to move around, a chart that shows composition at a glance, a workload view, and a fast path to the two things a manager actually changes here — flagging a hole urgent and assigning it to someone.

What changed from the reference, and why

  • Left sidebar → top nav. The reference uses a left rail; CoreChain already has a top-bar nav pattern built for /admin (AdminNav). Extending that instead of introducing a second nav paradigm keeps the app internally consistent — the same choice the app already made once.
  • Generic search → jump to a hole. "Search tasks, people, projects" has no equivalent backend here. A real, typeable hole-ID lookup is buildable today; a fake search box is not.
  • Donut + trend line → holes-by-status bar + workload list. No charting library is installed. A composition bar and a sorted list are honest with the data actually available, and match the app's existing hand-rolled progress-bar style rather than pulling in a new dependency for one screen.
  • "Create New Task" → Quick actions (flag urgent / assign). CoreChain has no generic task concept; a manager's two real actions here are flagging urgency and assigning a hole, which is what the panel does.
  • Goals & Milestones → omitted. Not a CoreChain concept. Nothing was invented to fill the slot.

Still true from the first mockup

  • It does not edit a geologist's records, only assignment, priority and read-only progress.
  • It never shows a number without its age — "as of" stays on every view.
  • It does not score people. The workload list is for spotting an uneven week, not a league table.
  • Same holes table data as today's built page, reorganised into filter tabs and a dedicated Quick actions panel instead of a control on every row.
